Dry-run deployment plan
- Print commands without changing the server:
  node mission-control/tools/vps-deploy.cjs plan --host 2.57.90.95 --repo <private-repo-url> --domain <domain>
- Read the printed target directory, image name, container name, and volume before executing:
  /opt/mission-control
  mission-control:<timestamp-or-tag>

  mission-control-data volume mounted at /app/data

Execute only after checks pass
- Deploy image and container only after owner provisioning/SSH access is complete and these Docker files are committed/pushed to the repo the VPS will clone:
  node mission-control/tools/vps-deploy.cjs deploy --host 2.57.90.95 --repo <private-repo-url> --domain <domain> --execute
- The deploy helper installs Docker if missing, clones/updates the committed remote repo on the VPS, builds the image on the VPS, creates mission-control-data, and runs docker compose up -d --build.
- Verify on the VPS:
  docker ps --filter name=mission-control --format 'container={{.Names}} image={{.Image}} status={{.Status}} ports={{.Ports}}'
  docker inspect mission-control --format 'health={{if .State.Health}}{{.State.Health.Status}}{{else}}none{{end}} restart={{.HostConfig.RestartPolicy.Name}}'
  docker volume inspect mission-control-data --format 'volume={{.Name}} mountpoint={{.Mountpoint}}'
  curl http://127.0.0.1:3000/api/status
- Verify from this machine only after the firewall/exposure choice permits it:
  curl http://2.57.90.95:3000/api/status or curl http://<domain>/api/status depending on exposure choice.

DNS and TLS
- DNS A record points to the new VPS only after the container answers http://127.0.0.1:3000/api/status locally on the VPS.
- If HTTPS is required, configure nginx/Caddy/Hostinger proxy and Let's Encrypt after DNS resolves to the VPS.
- Do not turn off the local Mission Control path until remote health, data persistence, and rollback are all proven.

Rollback readiness
- Record the image tag printed by every successful deploy.
- Confirm at least one previous image exists before cutover:
  docker images 'mission-control' --format '{{.Repository}}:{{.Tag}} {{.CreatedSince}}'
- Rollback mechanism is image tag reversion, not reinstalling bare Node or editing a systemd service:
  node mission-control/tools/vps-deploy.cjs rollback --host 2.57.90.95 --tag <previous-image-tag> --execute
- Rollback must preserve mission-control-data. Never delete the volume as part of an image rollback.
