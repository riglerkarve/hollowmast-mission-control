## The rules that matter more this week than any task

**1. Commit at the end of every working block, not at the end of the day.**
`tools/codex-run.cjs` owns git so your sandbox does not have to. Four other sessions share this
checkout, and a whole-file commit from a session holding a stale copy reverts by content with no
conflict and no warning. It has destroyed finished work four times in a single day. Twenty-six
uncommitted files were sitting in this tree an hour ago; they are committed now, and the count
should never get near that again.

**2. If a check fails and you did not cause it, STOP AND WRITE IT DOWN.** Do not fix it, do not
work around it, do not carry on past it. With nobody to ask, an unexplained failure is the most
valuable thing you can hand back — and the most dangerous thing to paper over.

**3. Never write to `data/dashboard.db` from a test.** Use a temp path and NAME that path in the
output, so a reader can tell the live file was never opened for writing rather than trusting it.

**4. Do not start anything you cannot finish and verify in one block.** A half-built change left
over a weekend is worse than no change: the next session cannot tell it from a mistake.

**5. Nothing reaches the owner until Sunday.** Anything for him goes under *Blocked on you* in a
handover. There is no urgency exception short of a **P0** — active data loss, a live security
hole, or a defect that invalidates work already done.

## Thursday — prove the tools you built actually measure what they claim

You built ten tools last night and they are committed. **Not one has been shown to work.** They
parse; that is all anyone knows.

That is the whole job for Thursday, and it is not a formality: a verification tool that silently
measures nothing is worse than no tool, because the project then believes it is covered.

| Tool | The question to answer |
|---|---|
| `migrate-from-zero.cjs` | Does it actually build a schema from empty, and does it FAIL when a migration is broken? Break one deliberately in a copy and check it says so. |
| `restore-backup.cjs` | Does the restored database really open and read? Prove it cannot touch the live file — by construction, not by intent. |
| `endpoint-shapes.cjs` | Change one route's response shape and confirm the diff catches it. Then revert. |
| `verify-checkers.cjs` | It checks other checkers, so it needs the same treatment: make it pass a checker that is broken, and confirm it notices. |
| `figure-ownership.cjs` | Does it report a disagreement that is really there, and stay quiet when there is not one? |
| `tool-audit.cjs` | Does an uninstrumented tool read as `never-run`? That conflation was the whole risk. |
| `verify-access-log-floor.cjs` | Does it still hold, and does it name any NEW unlogged path? |
| `verify-restart-lock.cjs` | Two restarts at once — does the lock actually serialise them? |

**For each: stage the positive.** Plant the defect, confirm it is caught, remove it, confirm the
removal is clean. A probe that has never been seen failing is not a probe.

**Deliverable:** a handover naming, for every tool, whether it was seen to fail. Any tool that
passed both with and without a planted defect is BROKEN and must be reported as such, not fixed
in the same breath.

and missed the same two items. That is a signal about the ORACLE, not the models. Before reading
83% as a ceiling on capability, check whether the rule is wrong on those two.

## Agentic AI — the gated track, and why it is a reading week

Workspace `CLAUDE.md` sequences this as **scheduled Claude runs → MCP servers → local Ollama**,
weeks 8–11, and expects at least one gate to be answered "no". Backlog **#17** is the open item
(*"Investigate MCP such as Higgsfield"*).

**This week it is investigation only, and that is a deliberate limit rather than caution.** An
MCP server is a standing capability that runs when nobody is watching, and installing one during
four unattended days is the exact opposite of how the rest of this workspace is built. The gate
comes before the build.

**What to produce — a written answer to four questions, filed as a backlog item, no code:**

1. **What would an MCP server here actually DO that a `.cjs` tool cannot?** The honest answer may
   be "nothing yet". Forty tools already run against this database with no protocol between them.
2. **What does it cost to keep?** A standing server is a thing that can silently stop, and this
   workspace already has four scheduled tasks that must not break.
3. **Where would it sit against the module contract?** One route file owns its tables; a protocol
   that reaches across modules breaks the rule the whole architecture rests on.
4. **What does it expose?** The dashboard binds `0.0.0.0` and holds ten account-years of bank
   transactions. Anything that opens a second door needs the same answer the `/garage` allowlist
   needed, and "it is only local" is no longer a sufficient answer — Ollama Pro proved that a
   localhost URL says nothing about where data goes.

**The recommendation to test, rather than the conclusion to reach:** the agentic capability this
workspace actually gained today came from *roles, handovers and a routing table* — not from a
protocol. Codex became useful because it was given ownership, a brief and an independent review
duty, none of which required MCP. If the four answers above do not produce a job MCP does better
than a script, the correct outcome is a recorded **no** with its reasoning, and that is a
successful week for this track rather than a failed one.

## If something breaks and there is nobody to ask

| What happened | What to do |
|---|---|
| The server is down | `node tools/restart.cjs` — it verifies the PID moved AND the service answered. Never `schtasks /end`; it reports SUCCESS and leaves the process running. |
| A checker fails and you did not touch it | Stop. Write it up. Do not fix it and do not proceed past it. |
| `migrate-from-zero` fails | **P0.** Stop everything, write it up, do nothing else. It means the backup may not be restorable. |
| A file changes under you | Another session is live. Stop, commit what is yours with `--only`, and say so — this premise-break invalidates any exclusive-access assumption. |
| A test wrote to the live database | Stop. The nightly backup at 23:55 is the recovery path and it is 14 days deep. Say exactly what was written. |
| The backup did not run | Report it. Do not run it manually — the chain's value is that it is unbroken and automatic, and a hand-run entry hides a broken schedule. |
| You are unsure whether something is yours | It is not. Write it in the handover and leave it. |

## What this week is actually for

Everything before tonight was **building**. This week is **proving** — that the schema rebuilds,
that the backup restores, that the checkers can fail, that the figures agree, and that the
dashboard's claims about itself survive contact with a test.

None of that is visible work and none of it will look impressive on Sunday. It is the difference
between a system that is trusted and one that is merely untested, and the only way to tell them
apart is to try.
