## The provenance work — what it actually was

**The symptom:** 60% of logged data accesses read as `unknown` — 1,431 of 2,402.

**The wrong fix I nearly made:** consolidating the 14 panel `api()` wrappers to send
`X-MC-By`. Decomposing first showed **all 16 panels already send it**, so that work
would have changed nothing at all. The server also runs no periodic work — no
`setInterval` in `index.js` or any route — so there were no request-less reads there
either.

**The real cause:** every script that does `require('../server/db')` runs outside a
request, so it falls back to `processActor`, and **not one of them called
`setProcessActor`**. Thirteen callers, all silent.

**What is now true:**

```
schedule   scripts/briefing.cjs
claude     business-split-report, categorise-model, classify-senders,
           rent-affordability, seed-rules, tax-year-report
import     import-browsing, import-claude-sessions, import-drive,
           import-gmail, import-samsung-health, import-starling
```

`server/provenance.js` owns the vocabulary and it is now
`['you', 'claude', 'import', 'schedule']`. The fourth value was **your decision** —
a scheduled job is none of the other three, and recording it as `claude` would have
been a wrong attribution, which that module exists specifically to prevent.

## Traps this machine set today

- **`sed` multi-line append collapses against CRLF.** It merged four comment lines
  into one inside `server/provenance.js`. Valid JS, so nothing failed — caught only
  by reading the result back. Now recorded in the workspace `CLAUDE.md`.
- **Backslashes are eaten in transit through the shell.** `/\r?\n/` written into a
  file through a quoted heredoc arrived as a literal newline, twice. Use a `.cjs`
  script written with the Write tool for anything containing escapes.
- **The `Edit` tool cannot match multi-line strings in these files** — they are all
  CRLF and the match string is LF. Single-line matches work; for multi-line, use a
  node script that splits on both endings and rejoins with the file's own EOL.
- **`node --check` reads `.js` as CommonJS** and so passes broken ES modules. For a
  panel, use `node --input-type=module --check < file`.
- **An exit code from a pipeline is the last command's.** Checking `$?` after
  `node ... | grep ...` gives grep's status. Measure node's directly.
- **The access log is buffered on a 10s timer.** Reading it immediately after a
  write shows no change, which looks exactly like a rejected write.
